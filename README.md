# Научный агент: практикум

Курс для исследователей: как пользоваться агентом так, чтобы результат можно
было защитить. Не «как написать харнес», а «как получить отчёт, где каждое
число имеет источник».

Адаптация курса [justxor/agent-harness-course](https://github.com/justxor/agent-harness-course)
(MIT, © 2026 justxor) под научную работу: литературный обзор, извлечение
методик из статей, проверка цитат, сборка документа по ГОСТ.

## Чему научитесь

1. **Пользоваться pi** как научным инструментом: модели, MCP-источники,
   скиллы, headless-режим.
2. **Понимать, где агент врёт** — прочитать свой мини-харнес (~1000 строк) и
   увидеть места, где теряются факты.
3. **Проверять утверждения** — механизм «цитата или ничего» с метриками и
   eval-набором.
4. **Собирать артефакт** — markdown → docx по ГОСТ с машинной приёмкой (18
   проверок).

## Быстрый старт

```bash
cd ~/projects/sci-agent
make setup         # один раз: .venv с pytest, ruff, mypy
make test          # тесты, без ключей и сети
make lessons       # все уроки 00…06
make evals         # 15 кейсов, precision/recall
make capstone      # обзор литературы из examples/sources

pi --list-models ollama    # что доступно на вашей машине
pi mcp list                # сколько инструментов подключено
```

Всё в `examples/` работает **без ключа и без сети**: там фейковая модель.
Живые прогоны — через `pi` или флаг `--live` в capstone.

## Три правила курса

1. **Цифры из команд, а не из документации.** Версии моделей, число
   инструментов, доступные флаги — брать из `pi --list-models`, `pi mcp list`,
   `pi --help` на своей машине прямо сейчас. Всё написанное здесь устареет.
2. **Цитата или ничего.** Утверждение без дословной цитаты и локатора не
   существует. Ссылка, которую вы не открыли, считается выдуманной.
3. **Измеряйте.** Улучшение без числа (precision, recall, цена, время) —
   самообман. Каждый инцидент с агентом превращается в кейс в `evals/cases.py`.

## Поддерживаемая среда

Курс рассчитан на использование в операционной системе **RED OS 8** (РЕД ОС 8).
Это основная среда: инструкции, команды установки и проверки написаны под неё,
стенд собран и прогнан именно там.

Проверено 8 ноября 2026 в RED OS 8.0.2 (чистая установка, репозитории `os` и
`updates`):

| что | результат |
|---|---|
| `python3` | 3.11.15 (в поставке) |
| `sudo dnf install -y python3-pip git make` | код 0: `python3-pip 25.1.1`, `git 2.53.0`, `GNU Make 4.4.1` |
| venv + `pip install python-docx` | код 0, `python-docx 1.2.0` |
| `git clone` + `make setup` | код 0 |
| `make test` | 83 теста проходят |
| `make docx` | 6/6 PASS |
| Node.js 22.23.4 из архива + `pi` 1.5.0 | код 0 (в репозитории RED OS 8 только Node 20.12.1, а `pi` требует ≥ 22.19) |

Что важно знать при установке:

- без ключей и без сети работают все уроки `examples/`, тесты, кейсы `evals/`,
  сборка и приёмка документа — то есть курс проходится и до получения ключа;
- `pandoc` в RED OS 8 версии 2.14.0.3 и для встроенной сборки **не нужен**:
  модуль 4 закрывается пакетом `gost/` на `python-docx`;
- `pi` ставится в домашний каталог: `~/.local/bin` уже есть в `PATH`
  (см. `/etc/skel/.bashrc`), права root не требуются;
- официальные зеркала `repo.red-soft.ru` и `repo1.red-soft.ru` из учебной сети
  могут не отвечать (HTTP 000); рабочие зеркала — зеркала вуза или
  `mirror.yandex.ru/redos/`.

На другом Linux (Debian/Ubuntu, ALT, Astra) курс тоже работает: нужны те же
Python 3.10+, `git`, `make`, а установка пакетов делается средствами этого
дистрибутива. На Windows нужен WSL или виртуальная машина: путь установки
отличается, и преподаватель в аудитории помочь не сможет.

Пошаговая установка с нуля — [docs/06-red-os-8.md](docs/06-red-os-8.md)
(пакеты, Node.js 22, `pi`, ключ, первый зелёный прогон).

## Окружение

Python 3.10+, `git`, `make`. Основная и проверенная среда — RED OS 8 (см.
раздел выше); на других дистрибутивах Linux курс работает, отличия только в
командах установки пакетов. `make setup` создаёт `.venv` и ставит pytest, ruff,
mypy и python-docx — без этого `make test` падает с «No module named pytest».
Дальше `make` подхватывает `.venv/bin/python` сам. Модуль 4 работает без
`pandoc`: сборка и приёмка живут в `gost/` на `python-docx`; `pandoc` нужен
только для пути с внешним скиллом (см. [docs/04](docs/04-приёмка-гост.md)).


## Что взято из исходного курса

Взято: архитектура мини-харнеса, идея eval-набора с фейковым HTTP-сервером,
песочница рабочей папки, обрезка истории по порогу без разрыва пар
tool-call/tool-result.

Переработано: все примеры заменены на научные задачи (извлечение методик,
проверка цитат) вместо калькулятора и магазина; убраны фоновые задачи и
субагенты; добавлены журнал провенанса, проверка чисел в цитатах, модуль
приёмки ГОСТ и сравнение с базовой линией «эвристика без модели».
