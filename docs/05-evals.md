# 05. Evals: как понять, что стало лучше

Модуль на 1.5 часа. Цель — число, которое меняется, когда вы меняете агента.

## Зачем

Без набора кейсов любое улучшение проверяется фразой «вроде стало лучше». Через
неделю вы не вспомните, что именно поменяли и почему это помогло. Eval-набор —
это память проекта.

## Минимальный набор

15 кейсов хватает, чтобы поймать регрессию. Каждый кейс — четыре поля:

```python
Case(id=4, quote="...", source="ivanov2024", expect_found=False,
     why="подмена числа: 88 Вт → 95 Вт")
```python

Обязательно должны быть обе стороны:

- **положительные** (цитата верна → должна быть принята);
- **отрицательные** — подмена числа, перестановка слов, цитата из другого
  источника, выдуманная фраза (должны быть отвергнуты).

Набор только из положительных кейсов всегда даёт 100% и ничего не измеряет.

## Метрики

```text
precision = принято верных / (принято верных + принято ложных)
recall    = принято верных / (принято верных + отвергнуто верных)
```

Для научного текста **precision важнее**: пропущенная ложная цитата дороже, чем
лишняя ручная проверка. Поэтому набор должен содержать достаточно
отрицательных кейсов — иначе precision нечем уронить.

## Как формулировать кейс, чтобы он был полезен

Плохо: «цитата не из источника».
Хорошо: «цитата дословна, но взята из раздела "Ограничения", где авторы сами
опровергают результат». Такой кейс проверяет уже не совпадение строк, а
`locator`, и сразу показывает границу метода.

Правило: **каждый новый инцидент с агентом превращается в кейс.** Агент сослался
на несуществующую статью — это кейс 16, а не запись в блокноте.

## Запуск

```bash
python3 -m evals.run_evals     # таблица + precision/recall + разбор провалов
python3 examples/06_eval.py    # то же с объяснениями, что менять
```

Код возврата 0 только при полном совпадении с разметкой — это позволяет
поставить evals в CI и не пускать регрессию.

## Куда расти

- **Стоимость.** Добавьте в кейс `tokens_used` и считайте цену одного
  подтверждённого утверждения. Удвоение качества за десятикратную цену — не
  всегда то, что нужно.
- **Задержка.** Для интерактивной работы 30 секунд на утверждение — предел.
- **Устойчивость.** Прогоните набор дважды: если вердикты расходятся — детектор
  нестабилен (или в нём есть случайность — её надо убрать).
- **Реальные трейсы.** Сохраняйте `trace.jsonl` хотя бы раз в неделю: потом
  видно, как менялось поведение, и это лучший материал для отчёта.
