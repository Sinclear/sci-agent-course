# 01. Среда: pi как научный инструмент

Модуль на 1.5–2 часа. Цель — рабочая сессия, которая читает источники и не
спрашивает разрешения на каждое чтение.

## Правило первое: цифры из живой команды

Всё, что написано в любом руководстве (включая этот файл), может быть
устаревшим. Источник истины — ваш компьютер:

```bash
pi --version
pi --list-models ollama        # какие модели реально доступны
pi mcp list                    # какие серверы и сколько инструментов
pi --help                      # флаги вашей версии
```

На машине, где писался курс (2026-10-31): pi 1.4.0, провайдер `ollama-cloud`,
22 модели, 4 MCP-сервера и 78 инструментов. Это **не** константы: через месяц
их будет больше. Учебный материал учит получать эти числа, а не запоминать их.

## Выбор модели под задачу

| Задача | Что брать | Почему |
|---|---|---|
| прочитать 20 PDF и выписать методики | модель с большим контекстом | иначе статья режется на куски и теряется связь разделов |
| проверить цитаты по списку | самая дешёвая быстрая | операция механическая, «ум» не нужен |
| написать введение | самая сильная из доступных | здесь как раз нужен язык и структура |
| разметить 300 утверждений | дешёвая + пакетная обработка | ошибка одного утверждения не критична, важна цена |

Проверка: одна и та же задача на двух моделях, сравните не «нравится/не
нравится», а три числа — сколько утверждений подтвердилось, сколько
инструментов вызвано, сколько стоило.

## Headless: агент без спроса

```bash
pi -p "прочитай docs/статья.pdf и выпиши методику в 5 строк"
```

В неинтерактивном режиме всё, что требует подтверждения, **блокируется**.
Поэтому делить инструменты надо заранее:

- **чтение** (поиск, чтение файлов, поиск по arXiv/КиберЛенинке) — проходит молча,
  если у инструмента объявлен признак «только чтение»;
- **запись** (скачать статью, создать файл) — спросит в интерактивной сессии и
  заблокируется в `-p`.

Отсюда рабочая схема: длинную работу запускайте headless только на чтение, а
всё, что пишет на диск, — отдельным шагом с подтверждением.

## Скиллы: ваш регламент, а не промпт в чате

Скилл — файл `SKILL.md` в `~/.pi/agent/skills/<имя>/`, который подгружается
по требованию. Два полезных для науки:

- `academic-style` — научный русский, структура статьи, антипаттерны;
- `document-analysis` — как вынимать текст из PDF/DOCX/XLSX и цитировать с
  локаторами.

Проверьте, что у вас есть:

```bash
ls ~/.pi/agent/skills/
```

Если чего-то нет — это первое практическое задание: написать свой скилл на
40 строк со своим регламентом (какой стиль ссылок, какая структура отчёта,
какие слова запрещены).

## Мини-практика

1. `pi --list-models ollama` — выпишите модели с большим контекстом.
2. `pi mcp list` — посчитайте, сколько у вас инструментов. Запишите число.
3. Задайте в `-p` вопрос по одной статье из своей папки и посмотрите, какими
   инструментами агент воспользовался. Если он ответил **без** чтения файла —
   ответ выдуман.
