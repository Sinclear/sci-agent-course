# 06. Установка на RED OS 8: проверенный путь

Курс рассчитан на использование в **RED OS 8** (РЕД ОС 8). Этот документ — что
именно выполняется на чистой установке, в каком порядке и с каким результатом.
Всё проверено 8 ноября 2026 на RED OS 8.0.2, репозитории `os` и `updates`.

## Что есть в системе сразу

    python3    3.11.15
    dnf        есть
    curl, tar  есть

Чего нет в базовой поставке и что придётся установить:

    python3-pip   pip в системе отсутствует
    git           нужен для клонирования курса
    make          им запускаются тесты, уроки, сборка
    node, npm     нужны только для `pi` (живые прогоны)
    pandoc        НЕ нужен: сборка и приёмка встроены в `gost/`

## Шаг 1. Пакеты

    $ sudo dnf install -y python3-pip git make

Проверенный результат: код возврата 0, установлены `python3-pip 25.1.1`,
`git 2.53.0`, `GNU Make 4.4.1`.

Если не так: `Unable to download metadata`, `All mirrors were tried` — проблема
сети или зеркал, а не с курсом. Официальные зеркала `repo.red-soft.ru` и
`repo1.red-soft.ru` из учебной сети могут не отвечать (HTTP 000). Рабочие
варианты: зеркало вуза или `https://mirror.yandex.ru/redos/8.0/x86_64/`.
Проверить подключение — `curl -sI https://mirror.yandex.ru/redos/8.0/x86_64/ | head -1`.

## Шаг 2. Курс и окружение

    $ git clone https://github.com/Sinclear/sci-agent-course.git
    $ cd sci-agent-course
    $ make setup
    $ make test

Проверенный результат: `make setup` создаёт `.venv`, ставит `pytest`, `ruff`,
`mypy`, `python-docx 1.2.0`; `make test` печатает `83 passed`.

Дальше проверяется, что курс работает целиком:

    $ make lessons      # 7 из 7 OK
    $ make evals        # 15 из 15, precision=recall=1.000
    $ make docx         # 6/6 PASS, код 0

Эти четыре команды не требуют ни ключа, ни сети — кроме `git clone` и `make setup`.
Если ключа нет, курс проходится до модуля живых прогонов включительно.

## Шаг 3. Node.js 22 для `pi`

`pi` требует Node.js не ниже 22.19.0. В репозиториях RED OS 8 максимум
`nodejs 20.12.1`, поэтому официальный архив ставится в домашний каталог, без
root:

    $ cd ~
    $ curl -LO https://nodejs.org/dist/latest-v22.x/node-v22.23.4-linux-x64.tar.xz
    $ sha256sum node-v22.23.4-linux-x64.tar.xz

Ожидаемая сумма:

    1805bcd35e6815559bd2eb97db438d3fdb0eb3a5e6a977b7c1badca76337e9ce

Если сумма не совпала — файл скачан не полностью, повторите загрузку. Дальше:

    $ mkdir -p ~/.local/node
    $ tar -xJf node-v22.23.4-linux-x64.tar.xz -C ~/.local/node --strip-components=1
    $ ~/.local/node/bin/node -v      # v22.23.4
    $ ~/.local/node/bin/npm -v       # 10.9.9

Добавлять `~/.local/node/bin` в `PATH` не обязательно: можно вызывать по полному
пути. Если удобнее, добавьте строку в `~/.bashrc` сами — курс не правит ваши
файлы настройки.

## Шаг 4. `pi` в домашний каталог

    $ ~/.local/node/bin/npm install -g --prefix ~/.local @earendil-works/pi-coding-agent
    $ ~/.local/bin/pi --version      # 1.5.0

`~/.local/bin` уже присутствует в `PATH` у нового пользователя: RED OS 8
добавляет его в `/etc/skel/.bashrc`. Поэтому после открытия нового окна терминала
достаточно команды `pi`.

Проверенный размер установки — 158 МБ.

Если не так: `Unsupported engine` означает, что `npm` взял системный Node 20, а
не 22. Запускать нужно именно `~/.local/node/bin/npm`, как в команде выше.

Если не так: `pi: команда не найдена` — открыто старое окно терминала, `PATH` не
перечитан, либо установка шла без `--prefix ~/.local`.

## Шаг 5. Ключ и первый живой прогон

Ключ выдаётся в личном кабинете провайдера моделей; порядок описан в документации
провайдера и меняется чаще, чем курс. Полученный ключ передаётся `pi`
штатным способом входа; в репозиторий и в отчёты он не попадает.

Признак успеха — `pi` видит модели и инструменты:

    $ pi --list-models
    $ pi mcp list

## Чего не нужно

- ставить `pandoc`: модуль 4 закрывается пакетом `gost/` на `python-docx`;
- ставить LibreOffice: сборка и приёмка работают без него; для оглавления с
  номерами страниц в учебном пособии используется отдельный сборщик;
- запускать `sudo` для Node.js и `pi`: обе устанавливаются в домашний каталог;
- выключать проверку подписи пакетов `dnf` или менять системные настройки.

## Другие системы

Курс работает и на другом Linux: нужны те же Python 3.10+, `git`, `make`,
установка пакетов средствами дистрибутива. На Windows требуется WSL или
виртуальная машина. Различия в установке описаны в этом документе, а не в
README, именно потому, что README фиксирует основную среду — RED OS 8.
