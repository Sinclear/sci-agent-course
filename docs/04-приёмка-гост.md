# 04. Приёмка артефакта: markdown → ГОСТ-docx → проверка

Модуль на 2 часа. Цель — документ, который проходит машинную проверку
оформления, а не «выглядит прилично».

## Что установлено и проверено

Проверено на этой машине 2026-10-31:

```text
скилл:   ~/.pi/agent/skills/gost-lab-report/   (scripts/build.py, verify.py, check_env.py, update_fields.py)
venv:     ~/.local/share/gost-docx-venv/        (python-docx 1.2.0, docxcompose)
pandoc:   3.12.1
LibreOffice: НЕТ
```

Установка с нуля:

```bash
git clone --depth 1 https://github.com/Bbar0n234/gost-report-skill.git "$TMPDIR/gostsrc"
cp -a "$TMPDIR/gostsrc/gost-lab-report" ~/.pi/agent/skills/
python3 -m venv ~/.local/share/gost-docx-venv
PIP_USER=0 ~/.local/share/gost-docx-venv/bin/pip install python-docx docxcompose
pkg install pandoc          # Termux; на Debian/Ubuntu — apt install pandoc
```

`PIP_USER=0` обязателен на Termux: иначе pip внутри venv пытается писать в
пользовательскую схему и падает. Проверка окружения —
`~/.local/share/gost-docx-venv/bin/python ~/.pi/agent/skills/gost-lab-report/scripts/check_env.py`.

## Конвейер

```
черновик.md  →  build.py  →  report.docx  →  verify.py  →  18 проверок
                  ↑                              ↓
        YAML-шапка (титул)            PASS / FAIL по каждому пункту
```

Шапка markdown задаёт титульный лист:

```yaml
---
title: "Название работы"
teacher_title: "канд. техн. наук, доцент"
teacher_name: "И.И. Петров"
lab_number: "1"
lab_title: "Название лабораторной"
discipline: "Дисциплина"
group: "1234"
student_name: "А.А. Иванов"
department: "Кафедра ИВТ"
---
```

Запуск:

```bash
python3 examples/05_build_gost.py      # учебный пример целиком
```

Или вручную:

```bash
~/.local/share/gost-docx-venv/bin/python ~/.pi/agent/skills/gost-lab-report/scripts/build.py  draft.md  report.docx
~/.local/share/gost-docx-venv/bin/python ~/.pi/agent/skills/gost-lab-report/scripts/verify.py report.docx
```

`verify.py` возвращает 0, только если все 18 проверок прошли. Это и есть
приёмка: не «на глаз», а код возврата, который можно поставить в CI.

## Если скилла нет: встроенная приёмка (6 проверок)

Скилл с 18 проверками — сторонний и в репозиторий не входит. Чтобы модуль не
зависел от него, в курсе есть учебный минимум:

```bash
.venv/bin/pip install python-docx        # один раз
python3 -m gost.build draft.md report.docx   # сборка: A4, поля, шрифт, интервал, PAGE
python3 -m gost.check report.docx            # приёмка: 6 проверок, код 0/1
```

Что проверяется (и что правится в первую очередь):

| № | Проверка | Требование |
|---|---|---|
| 1 | поля страницы | 30/15/20/20 мм, допуск 2 мм |
| 2 | основной шрифт | Times New Roman, 14 pt (стиль «Обычный») |
| 3 | интервал и отступ | 1.5, первая строка 1.25 см, до/после 0 |
| 4 | нумерация страниц | поле PAGE в колонтитуле |
| 5 | заголовки | стиль «Заголовок 1», а не жирный текст прописными |
| 6 | подписи | «Таблица N — …» / «Рисунок N — …», не «Рис.» |

Граница честная: это 6 проверок вместо 18. Не проверяются оглавление (поле
TOC), поля подписей, формулы, список источников и титульный лист по бланку
кафедры — это остаётся глазам и скиллу. Сборка встроенными средствами тоже
учебная: титульный лист проще, оглавление не генерируется. Если документ
нужен «как от кафедры» — ставьте скилл, он для этого и написан.

`make docx` использует тот путь, который доступен: скилл, если он есть, иначе
встроенный, и в обоих случаях возвращает ненулевой код, если приёмка не прошла.

## Что проверка НЕ делает

- **СОДЕРЖАНИЕ не обновляется.** Нет LibreOffice — поле TOC остаётся пустым.
  Открыть в Word, `Ctrl+A`, `F9`. На телефоне — Word или Collabora.
- **`{{PAGES}}` остаётся плейсхолдером.** Он подставляется тем же обновлением
  полей в Word, что и СОДЕРЖАНИЕ. `check_env.py` предупреждает об этом честно.
- **Смысл подписей** не проверяется: «Рисунок 1 — зависимость» формально
  корректно, даже если на рисунке таблица.
- **Список литературы** проверяется по оформлению, но не по существованию
  источников. Существование — задача модуля 3.
- **Числа** берутся откуда угодно. Если вставите цифру из черновика, а не из
  журнала утверждений, проверка этого не заметит.
- **Встроенная приёмка (6 проверок)** не видит оглавление, формулы и список
  источников: она ловит только развалившееся оформление. Полные 18 проверок —
  только у внешнего скилла.

## Порядок, который экономит часы

1. Сначала таблица утверждений (`sci_harness/provenance.py`), потом текст.
2. Текст пишется **из** таблицы: каждое предложение с числом имеет ID.
3. Только после этого — сборка docx. Правки в docx не переносятся в markdown,
   источник истины — markdown.
4. Финальный проход: `verify.py` → открыть в Word → обновить поля → глазами
   проверить титул и подписи.

## Практика

Соберите документ из своего черновика на 2–3 страницы и добейтесь
`18/18 PASS`. Типичные провалы на первом прогоне: поля страницы, интервал,
отсутствие подписи у таблицы, «Рисунок» вместо «Рис.».
