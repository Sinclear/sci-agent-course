# Практикум: задания для обучающегося

Курс рассчитан на RED OS 8; проверенная установка среды — [../docs/06-red-os-8.md](../docs/06-red-os-8.md).

Семь заданий — по одному на модуль и итоговая работа. Каждое состоит из
четырёх частей: что сделать, чем проверить себя, что сдать, чек-лист.

Оценок и баллов нет. Признак выполненного задания — **команда, которая
отработала с кодом возврата 0**, и **артефакт**, который можно открыть и
проверить. Если проверка обещает «должно работать», а вы этого не видели —
задание не выполнено.

Работайте в своей копии репозитория:

```bash
git clone https://github.com/Sinclear/sci-agent-course.git
cd sci-agent-course
make test          # 83 теста, без ключей и без сети — это база
```

## Задание 1. Найти границы автоматизации

Модуль 1 · 1 ч практики · самостоятельная работа 2 ч

#### Что сделать

1. Прочитать `docs/00-границы.md`.
2. Запустить `python3 examples/00_boundaries.py` и прочитать три отказа.
3. Выписать в файл `my/claims-boundary.md` две колонки: слева задачи, которые
   вы **готовы** отдать агенту с проверкой, справа — те, где нужен человек.
   Не менее пяти строк в каждой колонке, по своей специальности.

**Чем проверить себя.** Каждая строка левой колонки должна допускать проверку:
что именно вы проверите в результате агента (цитату, число, ссылку). Если
проверить нечем — строка не в левой колонке.

**Что сдать.** `my/claims-boundary.md` и вывод команды, где видны все три
отказа.

#### Чек-лист

- [ ] знаю, как выглядит каждый из трёх отказов, и могу воспроизвести;
- [ ] в правой колонке есть хотя бы одна задача, которую коллеги обычно
      отдают агенту без проверки;
- [ ] для каждой левой строки сформулирована проверка.

## Задание 2. Рабочая сессия

Модуль 2 · 3 ч практики · самостоятельная работа 2 ч

#### Что сделать

1. Пройти `docs/01-среда-pi.md`, проверить, что `pi` отвечает и видит
   инструменты; запишите вывод проверок в `my/env.md` с датой.
2. Запустить `python3 examples/01_sources.py` — песочница: инструмент не
   выходит за пределы рабочей папки.
3. Запустить `python3 examples/02_agent_loop.py` — цикл на фейковой модели,
   затем на настоящей (если есть ключ).
4. Спросить у агента что-нибудь про свои статьи и **записать, сколько
   токенов** ушло на запрос (число, не «много»).

**Чем проверить себя.** `make lessons` — семь уроков должны пройти все.

**Что сдать.** `my/env.md` с датой, версией и выводом проверки; число
токенов на один запрос.

#### Чек-лист

- [ ] `make lessons` → все уроки OK;
- [ ] понимаю, за что списываются токены: системный промпт, история,
      результаты инструментов;
- [ ] знаю, какие действия в моей среде требуют подтверждения.

## Задание 3. Три прочитанных источника

Модуль 3 · 3 ч практики · самостоятельная работа 2 ч

#### Что сделать

1. Прочитать `docs/02-источники-mcp.md`.
2. Найти по своей теме три статьи и получить **полные тексты** в рабочую
   папку `papers/`.
3. Для каждой записать в `my/sources.md`: автор, год, где лежит файл,
   сколько страниц, один абзац — о чём статья.

**Чем проверить себя.** Откройте каждый файл и найдите в нём фразу, которую
вы процитировали в `my/sources.md`. Не нашли — источник не прочитан.

**Что сдать.** `papers/` с тремя текстами и `my/sources.md`.

#### Чек-лист

- [ ] три файла открываются локально;
- [ ] ни одна строка `my/sources.md` не основана только на заголовке из выдачи;
- [ ] знаю, какие операции с источниками требовали подтверждения.

## Задание 4. Журнал утверждений

Модуль 4 · 5 ч практики · самостоятельная работа 2 ч

Главное задание курса. Если времени мало — делайте его, остальные можно
сократить.

#### Что сделать

1. Прочитать `docs/03-проверка-утверждений.md` и `docs/glossary.md`.
2. Запустить `python3 examples/03_context_loss.py`: факт «88 Вт» теряется при
   сжатии истории, но остаётся в журнале. Это норма, а не баг.
3. Запустить `python3 examples/04_cite_matrix.py`: матрица проверок, включая
   отклонение подменённого числа.
4. По своим трём источникам собрать 10–15 утверждений через
   `python3 capstone/mini_review.py --sources papers --out my/review.md`
   (или вручную, если хотите контролировать формулировки).

**Чем проверить себя.** В отчёте ни одной строки без цитаты и локатора.
Найдите два-три отклонённых утверждения и объясните себе, **почему** они
отклонены: цитата не найдена, число не совпало, порог не пройден.

**Что сдать.** `my/review.md` и короткий разбор отклонённых (5–10 строк).

#### Чек-лист

- [ ] каждое подтверждённое утверждение имеет цитату и локатор;
- [ ] я проверил два локатора руками, открыв файл на указанном месте;
- [ ] могу объяснить, почему отклонено хотя бы одно утверждение, которое
      выглядело верным.

## Задание 5. Документ, проходящий приёмку

Модуль 5 · 3 ч практики · самостоятельная работа 2 ч

#### Что сделать

1. Прочитать `docs/04-приёмка-гост.md`, подготовить venv с `python-docx`
   (`make setup` делает это сам). `pandoc` нужен только для пути с внешним
   скиллом; для встроенной сборки он не требуется.
2. Запустить `python3 examples/05_build_gost.py`: собрать docx и увидеть
   приёмку.
3. Собрать свой отчёт:

```bash
python3 capstone/mini_review.py --sources papers --out my/review.md --docx
```

#### Чем проверить себя

Есть скилл — проверяем им (18 проверок):

```bash
~/.local/share/gost-docx-venv/bin/python \
  ~/.pi/agent/skills/gost-lab-report/scripts/verify.py my/review.docx
```

Скилла нет — проверяем встроенной приёмкой (6 проверок, `make setup` уже
поставил python-docx):

```bash
.venv/bin/python -m gost.check my/review.docx
```

Код возврата 0 — принято. Любой другой — читайте, какая проверка не прошла.

**Что сдать.** `my/review.docx` и вывод проверки (последняя строка с кодом).

#### Чек-лист

- [ ] `verify.py` (или `gost.check`, если скилла нет) → код 0;
- [ ] понимаю, какие проверки машинные, а какие остались ручными
      (оглавление, `{{PAGES}}`);
- [ ] знаю, что 6 встроенных проверок — не 18: оглавление, формулы и список
      источников встроенная приёмка не смотрит;
- [ ] знаю, что правка оформления не меняет содержание утверждений.

## Задание 6. Свой eval-набор

Модуль 6 · 1 ч практики · самостоятельная работа 2 ч

#### Что сделать

1. Прочитать `docs/05-evals.md`.
2. Запустить `make evals` — 15 кейсов, precision и recall.
3. Добавить в свою копию `evals/cases.py` не менее пяти кейсов по своей
   области: два положительных (верная цитата должна быть принята) и три
   отрицательных (подменённое число или пересказ вместо цитаты должны быть
   отклонены).
4. Посчитать precision и recall на своём наборе.

**Чем проверить себя.** `make test` — тесты проходят; `make evals` — ваш
кейс участвует в прогоне. Если отрицательный кейс **принимается**, проблема
в вашей проверке, а не в кейсе.

**Что сдать.** Свой `evals/cases.py` (diff) и числа precision/recall на
своём наборе.

#### Чек-лист

- [ ] не менее 10 кейсов, из них не менее 3 отрицательных;
- [ ] могу назвать число, а не «работает лучше»;
- [ ] знаю, чем отличается пропущенная выдумка от лишней ручной проверки, и
      какая из двух ошибок дороже в моей работе.

## Задание 7. Итоговая работа: обзор по своей теме

2 ч · выполняется самостоятельно, сдаётся преподавателю

Собственный источник **не менее трёх статей**, отчёт с цитатами, docx,
проходящий приёмку, и свой eval-набор из задания 6.

```bash
python3 capstone/mini_review.py \
    --sources papers --live --docx --out my/review.md
```

`--live` вызывает модель; без ключа запустите без него — отчёт соберётся
эвристикой, и этого достаточно, чтобы проверить пайплайн, но не достаточно
для сдачи.

#### Что сдать

1. `papers/` — источники;
2. `my/review.md` — отчёт;
3. `my/review.docx` и вывод `verify.py` с кодом 0;
4. `evals/cases.py` — свой набор кейсов;
5. `my/notes.md` — пять строк: что агент сделал хорошо, что пришлось
   переделывать, что вы теперь проверяете всегда.

#### Чек-лист, который использует преподаватель

- [ ] источников не менее трёх, все открываются;
- [ ] каждая строка отчёта имеет цитату и локатор;
- [ ] хотя бы одно отклонённое утверждение разобрано;
- [ ] `verify.py` → код 0;
- [ ] в наборе кейсов есть отрицательные, и они отклоняются;
- [ ] в `my/notes.md` есть хотя бы один вывод, который вы примените
      в следующей работе.

## Шаблон сдачи

```text
my/
├── claims-boundary.md   задание 1
├── env.md               задание 2
├── sources.md           задание 3
├── review.md            задания 4, 5, 7
├── review.docx          задания 5, 7
└── notes.md             задание 7
papers/                  три и более полных текста
evals/cases.py           задание 6
```

Папка `my/` и `papers/` в репозиторий не попадают: они уже в `.gitignore`.
Это сделано намеренно — источники часто под лицензией, а личные заметки не
являются частью курса.
